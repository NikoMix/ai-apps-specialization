## What the Auditor Checks

The auditor verifies that your organisation has **structured onboarding assets and delivery templates** for the AI on Azure services you sell and deliver — demonstrating that you enable customers systematically, not just reactively.

**Typical questions:**
- What onboarding materials do you provide to new customers?
- Do you have standard templates for AI solution delivery?
- How do you ensure customers can operate AI solutions independently after handover?

## Evidence Guidance

### Customer Onboarding Pack

The onboarding pack should include or cover:

- **Introduction to your organisation** — team structure, key contacts, escalation path
- **Engagement overview** — scope, timeline, milestones, deliverables
- **Communication cadence** — meeting frequency, reporting format, tools used
- **Azure environment standards** — naming conventions, tagging policies, governance baseline
- **Support model** — how ongoing support works post-go-live
- **Key contacts** — project lead, technical lead, Azure support paths

### Delivery Templates

Provide templates from at least two of the following categories:

| Category | Example Template |
|---|---|
| Discovery | Requirements questionnaire, stakeholder map, Azure readiness assessment |
| Design | High-Level Design (HLD) template, Azure architecture decision record (ADR) |
| Build | Sprint planning template, Definition of Done checklist, CI/CD pipeline template |
| Test | UAT test plan template, performance test report template |
| Deploy | Go-live checklist, hypercare plan template, rollback procedure |
| Handover | Closure report template, knowledge transfer agenda, support handover checklist |

### Knowledge Transfer Plan

A knowledge transfer plan should cover:

| Item | Details |
|---|---|
| **Scope** | What the customer needs to know to operate independently |
| **Format** | Documentation, hands-on workshops, recorded sessions |
| **Recipients** | Customer IT team, developers, business users |
| **Timeline** | Integrated into the final delivery phase |
| **Validation** | How you confirm the customer can operate the solution |

### Runbook / Operational Guide

An operational guide (anonymised) for an AI solution on Azure should include:
- Solution architecture overview
- Day-to-day operational tasks
- Monitoring and alerting setup (Azure Monitor, Application Insights)
- Common issues and resolutions
- Escalation contacts (Microsoft Support, your support team)
- Cost management guidance

## Sample Onboarding Timeline

| Week | Activity | Deliverable |
|---|---|---|
| 0 | Kickoff and environment access | Kickoff deck, environment setup guide |
| 1 | Discovery workshops | Requirements document, stakeholder map |
| 2–3 | Architecture review and design sign-off | HLD, ADRs |
| 4–N | Build and sprint reviews | Sprint reports, demo recordings |
| N-2 | UAT and knowledge transfer | UAT test plan, training sessions |
| N-1 | Go-live preparation | Go-live checklist, runbook |
| N | Go-live and hypercare | Hypercare log, daily stand-up |
| N+2 | Closure and handover | Closure report, support SLA |

## Common Gaps

| Gap | Remediation |
|---|---|
| No formal onboarding pack | Create a branded PowerPoint with the sections listed above — 10 slides is sufficient |
| Templates exist but are customer-specific | Generalise one customer's artefacts into a reusable template |
| Knowledge transfer is verbal only | Create a one-page KT plan template; even a checklist format is accepted |
| Runbook not documented | Export Azure Monitor dashboards and create a 5–10 page operational summary |
