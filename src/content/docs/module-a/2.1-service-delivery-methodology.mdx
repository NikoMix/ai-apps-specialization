## What the Auditor Checks

The auditor verifies that your organisation delivers services using a **documented, repeatable methodology** — not ad hoc processes. Evidence should demonstrate that the methodology is actively used in real engagements.

**Typical questions:**
- Is there a written delivery methodology or playbook?
- How are projects scoped, kicked off, and closed?
- Is there evidence the methodology was followed in recent customer engagements?

## Evidence Guidance

### Delivery Methodology Document

This is the cornerstone of this control. It should cover:

- **Phases:** Discovery → Design → Build → Test → Deploy → Handover
- **Artefacts produced at each phase** (what's created and who approves it)
- **Roles and responsibilities** at each phase
- **Quality gates** between phases
- **Tools used** (Azure DevOps, Jira, GitHub Projects, etc.)

A 5–10 page document is sufficient. It does not need to be ISO-certified, but should be version-controlled with an owner listed.

### Real Engagement Evidence

Provide **two or more anonymised project artefacts** from different customer engagements. Acceptable anonymisation:
- Replace customer name with "Customer A", "Customer B"
- Redact project-specific commercial details
- Leave delivery process artefacts intact (kickoff agenda, closure checklist, etc.)

### Version Control

All methodology documents should show:
- Document version number
- Last reviewed/updated date
- Owner or author
- Approval signature (even informal, e.g., Head of Delivery)

## Sample Delivery Phases Table

| Phase | Key Activities | Artefacts | Approver |
|---|---|---|---|
| Discovery | Requirements gathering, stakeholder mapping | Discovery report, RACI | Client sponsor |
| Design | Architecture, solution design, PoC | HLD, LLD, PoC report | Technical lead |
| Build | Development, integration, unit testing | Sprint reports, code repos | Delivery lead |
| Test | UAT, performance testing, security review | Test report, sign-off | Client sponsor |
| Deploy | Go-live, hypercare, knowledge transfer | Runbook, hypercare log | Delivery lead |
| Handover | Documentation, support transition, closure | Closure report, support SLA | Account manager |

## Common Gaps

| Gap | Remediation |
|---|---|
| Methodology exists but is undocumented (tribal knowledge) | Run a 2-hour workshop with delivery leads to capture and document the process |
| No real project artefacts available | Use a sandbox/internal project to generate demonstrative artefacts |
| Methodology document is a generic Agile description | Add your organisation's specific tooling, phase gates, and role definitions |
