## When to use this

Run the Azure Well-Architected Framework assessment after discovery and before Detailed Technical Design sign-off. Re-run it before go-live if the architecture changed materially, and treat the findings as mandatory inputs to architecture and operational planning.

- [Azure Well-Architected Framework for AI workloads](https://learn.microsoft.com/en-us/azure/well-architected/ai/)
- [Azure Architecture Review assessment](https://learn.microsoft.com/en-us/assessments/azure-architecture-review/)

## Inputs you need from the customer

| # | Input | Source | Format |
| --- | --- | --- | --- |
| 1 | Current or proposed architecture diagram | Solution Architecture Design | Diagram |
| 2 | Service Level Objective and Service Level Agreement targets by workload tier | Customer | Document |
| 3 | Threat model and identity assumptions | Customer security | Document |
| 4 | Cost target for the first 12 months | Customer finance | Numeric |
| 5 | Evaluation dataset or quality baseline for model behaviour | Engagement team | JSONL, CSV |

## Step-by-step

<Steps>
1. Start with the Azure Architecture Review to baseline the core cloud design and capture structural findings.
2. Run the Well-Architected Framework assessment with the customer architect, security lead, and delivery lead in the room.
3. Score reliability, security, cost optimisation, operational excellence, and performance efficiency with the AI workload lens applied.
4. Record each finding with severity, owner, target artefact, and required completion phase.
5. Update the Solution Architecture Design, Detailed Technical Design, runbook, or hypercare plan based on those findings.
6. Reconfirm critical findings before go-live.
</Steps>

## Mandatory Assessment Actions

| Finding type | Mandatory consultant action |
| --- | --- |
| Reliability gap | Add a remediation task into the architecture backlog and update the runbook or failover design before go-live. |
| Security gap | Record the control owner, update the security design, and confirm the customer risk owner accepts any deferred action. |
| Cost optimisation gap | Update sizing assumptions, quota plan, or workload architecture and re-baseline the cost model. |
| Operational excellence gap | Add dashboard, alerting, logging, or change-control requirements into the Detailed Technical Design and hypercare plan. |
| Performance efficiency gap | Run or schedule a benchmark, tune the design, and document the expected latency or throughput outcome. |
| Responsible AI gap | Update evaluation, content safety, human review, or prompt governance controls before the workload is accepted for production. |

## Output: customer-ready deliverable

Deliver the assessment export, prioritised remediation backlog, updated design decisions, and an executive summary that shows how the architecture improved as a result of the review.
