## When to use this

Run after a qualified customer is committed to a paid envisioning engagement, before any architecture work. The discovery workshop produces the decisions a Solution Architecture Design needs: prioritised use case, target architecture pattern, data strategy, and responsible-AI guardrails.

## Inputs you need from the customer

| # | Input | Source | Format |
| --- | --- | --- | --- |
| 1 | Scored qualification questionnaire | Previous step | Document |
| 2 | List of candidate use cases | Customer pre-read | List |
| 3 | Inventory of candidate data sources | Customer pre-read | Spreadsheet |
| 4 | Current Azure landing zone state | Customer architect | Diagram |
| 5 | Responsible AI policy (if any) | Customer | Document |
| 6 | Named workshop participants per day | Customer | Responsibility Assignment Matrix (RACI) |

## Step-by-step

The workshop is **two days**, one architect-led and one business-led. Send the workbook to the customer one week in advance; ask them to pre-fill Tabs 1–3.

<Steps>

1. **Day 1 morning — Use case framing.** Walk the candidate use cases. For each, score on value, feasibility, and risk. Pick the top 1–2 to take forward.

2. **Day 1 afternoon — Data strategy.** Inventory the data the chosen use case will use. For each source, capture: location, sensitivity, refresh cadence, owner, lineage. Identify any source that is not Azure-resident — these become migration or integration work items.

3. **Day 2 morning — Architecture & service selection.** Map the use case to a reference architecture pattern (see [Reference Architectures](../reference-architectures/)). Decide between Azure Container Apps, AKS, or App Service for the hosting tier. Decide between Azure Cosmos DB, Azure SQL, or Microsoft Fabric for the operational + analytical data tier.

4. **Day 2 afternoon — Responsible AI & operations.** Walk the Microsoft Responsible AI Standard at use-case level. Identify human-in-the-loop checkpoints, content filters, abuse monitoring, and the change-control flow for prompts and models.

5. **Closeout.** Agree on the next deliverable (almost always: Solution Architecture Design + costed proposal) and the date you commit to deliver it.

</Steps>

### Suggested agenda

| Time | Day 1 | Day 2 |
| --- | --- | --- |
| 09:00–10:30 | Welcome, scope, success criteria | Architecture pattern selection |
| 10:45–12:30 | Use case framing & scoring | Service selection (compute, data, identity) |
| 13:30–15:00 | Data inventory | Responsible AI walkthrough |
| 15:15–16:30 | Data flow & integration | Operating model + change control |
| 16:30–17:00 | Day-1 readout | Next steps + deliverable commit |

### Workshop kit contents

- **Deck** — facilitator's slide deck with all sections above
- **Workbook** — multi-tab Excel: Tab 1 Use cases, Tab 2 Data inventory, Tab 3 Architecture decisions, Tab 4 Responsible AI checklist, Tab 5 Next steps log

## Output: customer-ready deliverable

A signed-off **Discovery Report** (use the Solution Architecture Design template's "Discovery Findings" section) containing:

- Prioritised use case + success metric
- Target architecture pattern with chosen Azure services
- Data strategy with classified data flows
- Responsible-AI guardrails
- Costed proposal for the next phase
