## When to use this

Create the Knowledge Transfer plan during the build phase and baseline it before user acceptance testing starts. The plan should run through the final sprints, overlap go-live, and finish only after the receiving team can operate the workload without partner intervention.

## Inputs you need from the customer

| # | Input | Source | Format |
| --- | --- | --- | --- |
| 1 | Receiving roles, named individuals, and backup contacts | Customer delivery lead | Responsibility Assignment Matrix (RACI), org chart |
| 2 | Skills baseline for each receiving role | Customer manager | Self-assessment, interview notes |
| 3 | Training time budget and attendance expectations | Customer sponsor | Email, governance note |
| 4 | Platform access needed for labs and walkthroughs | Customer platform team | Access request list |
| 5 | Exit assessment sign-off authority | Customer sponsor | Governance note |

## Core plan structure

<Steps>
1. **Audience matrix** — define each role, the required end-state capability, and the sessions they must attend.
2. **Session catalogue** — list every session with owner, duration, prerequisites, learning objectives, and hands-on lab.
3. **Role curriculum** — map Microsoft Learn paths and internal artefacts to each audience.
4. **Hands-on validation** — specify the labs, simulations, or walkthroughs that prove the team can operate independently.
5. **Exit assessment** — define the tasks each role must complete and who signs off competency.
6. **Recording and artefact index** — every session recording, deck, runbook, and lab guide must be indexed in one place.
</Steps>

## Session catalogue template

| Session | Audience | Duration | Delivery mode | Objectives | Required artefacts |
| --- | --- | --- | --- | --- | --- |
| Solution walkthrough | All receiving roles | 90 min | Workshop | Understand business context, target architecture, and support boundaries | Solution Architecture Design, architecture diagram |
| Code and repository tour | Developers, platform engineers | 120 min | Pairing session | Build locally, run tests, understand branching and release flow | Repository README, CI/CD pipeline, environment guide |
| Prompt and evaluation governance | Developers, product owner, Responsible AI reviewers | 90 min | Workshop | Manage prompt changes, run evaluations, interpret quality results | Prompt catalogue, evaluation runbook |
| Operations and monitoring | SRE / Ops | 120 min | Hands-on lab | Use dashboards, alerts, KQL queries, and escalation flows | Runbook, dashboard links, alert catalogue |
| Security and access model | Security lead, platform team | 60 min | Walkthrough | Review identities, networking, data controls, and break-glass procedures | Access matrix, key vault design, network diagram |
| Go-live and incident drill | All operational roles | 120 min | Simulation | Practice incident handling, failover, rollback, and communication routines | Hypercare plan, incident runbook |

## Exit assessment criteria

| Role | Required demonstration | Evidence of completion | Sign-off by |
| --- | --- | --- | --- |
| Developer | Update a prompt, run the evaluation suite, and submit a change through CI/CD | Pull request, evaluation output, deployment record | Delivery lead |
| SRE / Ops | Triage an alert, identify the likely cause, and execute the first-response procedure | Incident drill worksheet, dashboard screenshots | Service owner |
| Data Engineer | Re-run or validate the grounding data pipeline and confirm index freshness | Pipeline log, index status, validation checklist | Platform lead |
| Product or business owner | Explain the guardrails, escalation route, and acceptance criteria for future changes | Recorded walkthrough, sign-off form | Executive sponsor |

## Exam preparation guidance

| Certification | Why it matters in handover | Official page |
| --- | --- | --- |
| AI-102: Azure AI Engineer Associate | Validates Azure AI workload design, responsible AI controls, and service integration capability | https://learn.microsoft.com/en-us/credentials/certifications/azure-ai-engineer/ |
| AZ-204: Azure Developer Associate | Validates application integration, automation, and cloud development capability for the receiving engineering team | https://learn.microsoft.com/en-us/credentials/certifications/azure-developer/ |

- Ask each receiving engineer whether they already hold one of the target certifications and whether exam prep should be part of the post-project enablement plan.
- Reuse the labs from the delivery project as certification preparation material so the customer learns in the context of their own solution.
- Where the customer is forming a new AI platform team, recommend a 30-, 60-, and 90-day learning roadmap after hypercare.

## Output: customer-ready deliverable

Deliver a signed Knowledge Transfer plan, a session and recording index, completed exit assessments, and a backlog of deferred knowledge gaps that still need customer action after project closure.
